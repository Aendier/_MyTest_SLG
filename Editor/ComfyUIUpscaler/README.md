# ComfyUI 图片批量高清化工具

一个 Unity 编辑器扩展：把工程内的 UI 贴图批量打包成图集，送到本地 **ComfyUI** 做超分/高清化，再拆分回原图并**原地覆盖**，同时保留完整的备份、历史与可恢复能力。

适用于 UI 分辨率升级场景：一次性对成百上千张 Sprite 做放大，且尽量不破坏原有的导入设置与九宫格（Border）信息。

## 核心特性

- **批量图集化处理**：用 shelf-packing 算法把多张小图打包进大图集，减少 ComfyUI 的推理次数，显著提升吞吐。
- **原地覆盖 + 全量备份**：所有源文件及其 `.meta` 在覆盖前完整备份，任何一步校验失败都不会污染源资源。
- **安全中断、断点续跑**：处理过程中可随时"中断"，已下载的图集页会保留；之后可从历史任务"继续"，不重复提交已完成的页。
- **异步可恢复（部分/强制）**：已完成的任务可"恢复"。恢复前先异步校验，并按备份哈希把资源分为**可安全恢复 / 任务完成后已变化 / 备份缺失**三类；详细确认框会给出数量、体积与粗估耗时，可选择**仅恢复安全项**或**强制全部恢复**。复制阶段分片执行、带进度、可中断。也支持在资源表里**单独恢复某一张**。
- **保持显示尺寸（PPU）**：可选开关；放大后按实际倍率同步缩放 `spritePixelsPerUnit`，让受 Layout/Native Size 控制的 UI 元素显示尺寸不变。
- **Sprite 元数据保留**：`Single` / `Multiple` 模式的 Sprite 会按放大倍率同步缩放九宫格 Border、pivot 等信息。
- **升级状态追踪**：为每个资源维护"未升级 / 已升级 / 已变化 / 上次失败 / 已回滚"状态，避免重复处理。
- **跳过标签**：可把文件夹或单个资源标记为"跳过"，扫描后这些资源不会被选中，也可在列表里隐藏。
- **实时显存监控**：执行期间每 2 秒轮询 ComfyUI `/system_stats`，显示实测占用峰值与可用显存，逼近上限时告警（仅提示，不强制阻止）。
- **异步不卡顿**：递归扫描、恢复、网络等待均为异步/时间分片，编辑器保持响应并可取消（结尾的资源导入受 Unity 限制会短暂占用主线程）。
- **Alpha 保留**：PNG 的 alpha 通道单独做双线性缩放后重新合并，避免半透明边缘劣化。

## 环境与依赖

- **Unity**：2022.3.x（开发验证于 2022.3.62f）。
- **Odin Inspector**：窗口基于 `OdinEditorWindow` 绘制，工程需已安装 Odin（Sirenix）。
- **程序集引用**：`ComfyUIUpscaler.Editor.asmdef` 引用了 `Unity.2D.Sprite.Editor`（读写 Sprite 元数据）。
- **ComfyUI**：本地或可访问的 ComfyUI 服务，且已导入好可用的放大工作流。

## 快速开始

1. 启动本地 ComfyUI（默认地址 `http://127.0.0.1:8188`）。
2. 在 ComfyUI 里调好放大工作流，用 **Save (API Format)** 导出为 JSON 文件（不是普通的工作流 JSON）。
3. Unity 菜单：**`UIR/ComfyUI 图片批量高清化`** 打开窗口。
4. 在「路径与扫描」里添加要处理的目录，点 **递归扫描**。
5. 在「ComfyUI 连接与工作流」里填地址、选择 API Format JSON、填好节点 ID，点 **测试连接** 确认可用。
6. 在「图集参数」里设置放大倍率等（见下文）。
7. 在「待处理资源」表里勾选要处理的图片（可用批量按钮）。
8. 点 **开始高清化**，确认弹窗后开始。完成并全部校验通过后会自动覆盖原图。

## 界面与配置项

窗口分为 **任务面板** 与 **历史记录** 两个页签。

### 路径与扫描

- **扫描目录 / 跳过的文件夹**：并排两列，均为**文件夹引用**（拖入或点选 `Assets` 下的目录即可，无需手填路径）；非法项会被自动剔除。
- **扫描目录**：要处理的目录。
- **跳过的文件夹**：这些目录（及其下资源）会被标记为"跳过"，扫描后不会被自动选中。
- **递归扫描**：递归收集目录下的 `.png` / `.jpg` / `.jpeg`，异步执行、可取消。

### ComfyUI 连接与工作流

| 配置 | 说明 |
| --- | --- |
| 地址 | ComfyUI 服务地址，默认 `http://127.0.0.1:8188` |
| API Format JSON | ComfyUI 导出的 **API Format** 工作流文件路径 |
| 输入图片节点 ID | 工作流中接收输入图片的节点 ID |
| 输入字段名 | 该节点里图片字段名，一般为 `image` |
| 最终输出节点 ID | 产出最终图片的节点 ID |
| 单请求超时（秒） | 单个 HTTP 请求的超时 |
| 单页超时（分钟） | 单张图集页从提交到产出的总超时 |
| 测试连接 | 调 `/system_stats` 验证连通并读取显存 |

### 图集参数

| 配置 | 说明 |
| --- | --- |
| 预期放大倍率 | 工作流最终输出相对输入的倍率，用于校验输出尺寸是否符合预期 |
| 保持显示尺寸 | 开启后按实际倍率同步缩放 `spritePixelsPerUnit`，让 UI 元素显示尺寸不变（默认开启） |
| Padding | 图集内每张图之间的间距（像素） |
| 最大边长 | 图集单边上限（1024/2048/4096/8192） |
| 最大像素数 | 图集总像素上限，控制单页内存 |
| JPG 质量 | 覆盖写回 `.jpg`/`.jpeg` 时的编码质量（1~100）；`.png` 无损写回 |

> 显存不再依赖手填的"峰值倍率/安全系数"来预估，改为执行期间**实时监控**（见下文）。

### 待处理资源

- 表格列：处理（勾选）、资源路径、升级状态、当前尺寸、升级记录、类型、Sprite 模式、九宫格/风险。
- **状态筛选**下拉 + 表内搜索 + **隐藏已跳过**开关。
- 批量按钮：**全选 / 仅安全项 / 取消已升级 / 全不选**（均会排除"已跳过"的资源）。
- 可在行内把资源标记为"跳过"。

### 执行进度与日志

- 显示预计图集页数、**实测占用峰值**、可用显存、内存告警、进度条与实时日志。
- 操作按钮：**开始高清化 / 中断 / 刷新显存**。

### 历史记录

上下两段式布局：

- **上半部**：左侧任务列表（可按状态筛选），右侧选中任务的详情与操作（**继续 / 恢复 / 打开目录**）；恢复进行中会在此显示进度条与**中断**按钮。
- **下半部**：该任务调整过的资源列表（Odin 表格，自带搜索、每页 25 条分页）。每行可**定位**到资源、或**单独恢复**该资源。

## ComfyUI 工作流要求

- 必须使用 ComfyUI 的 **Save (API Format)** 导出的 JSON。
- 工作流需要有一个明确的**输入图片节点**（其图片字段名与"输入字段名"一致，通常是 `image`）。
- 需要一个明确的**最终输出节点**（产出高清结果的节点）。
- 工作流内部的实际放大倍率要与「预期放大倍率」一致，否则输出尺寸校验会失败（见常见问题）。

工具会为每张图集页克隆一份工作流、注入上传后的图片名、提交 `/prompt`，然后轮询 `/history` 拿到输出节点的产物，再通过 `/view` 下载。

---

## 处理流程

1. **打包**：把勾选的图片用 shelf-packing 排进若干图集页（受最大边长/最大像素约束）。
2. **生成输入图集**：写出 `atlas-input/page-XXX.png`。
3. **逐页处理**：上传（`/upload/image`）→ 提交（`/prompt`）→ 轮询（`/history`）→ 下载（`/view`）到 `atlas-output/page-XXX.png`。
4. **拆分**：按放大倍率把输出图集拆回每张图，校验每页输出尺寸是否≈`输入尺寸 × 预期倍率`。
5. **暂存**：拆分结果写入任务目录的暂存区（按原图格式编码，PNG 保留 alpha）。
6. **备份**：把所有源文件及其 `.meta` 备份到任务目录。
7. **提交**：用暂存文件覆盖原图 → 批量重导入 → 同步 Sprite 元数据（Border/pivot 等）→ 校验引用与哈希。
8. **写报告**：生成 `report.txt` 与任务清单 `manifest.json`，更新升级映射表。

只有**全部**页都成功、拆分与尺寸校验都通过后，第 6~7 步才会执行；任何失败都不会覆盖源资源。

## 安全中断与续跑

- 点击 **中断** 会：向 ComfyUI 发送 `/interrupt` 停止服务端当前生成；取消本地流程；**保留**已下载的图集页。
- 异常终态为 `Failed` / `Canceled` / `RolledBack`。其中 `Processing`、`Canceled`、`Failed` 且**未提交**的任务，可在「历史记录」里点 **继续**：
  - 复用磁盘上已生成的 `atlas-input` 与已下载的 `atlas-output`，只重跑剩余页，再统一拆分与提交。
  - 续跑前会校验：工作流 **SHA-256** 是否一致、所有源图的 **GUID/文件** 是否仍存在且未变。任一冲突都会中止并列出原因。
  - 续跑所需的运行参数（超时、JPG 质量等）随 `manifest.json` 落盘，续跑不依赖当前窗口状态。

## 恢复（回滚）

「历史记录」里 **已完成（Completed）** 的任务可点 **恢复**，用备份覆盖回 `manifest` 记录的原文件及 `.meta`。整个过程是**异步、可中断**的：

1. **异步校验**：逐张比对当前文件/`.meta` 与任务输出的哈希，时间分片执行、带进度、可取消。按结果把资源分为：
   - **可安全恢复**：当前文件仍与任务输出一致；
   - **任务完成后已变化**：完成后又被改动（默认**跳过**，避免覆盖你的新改动）；
   - **备份缺失**：无有效备份，**始终跳过**。
2. **详细确认框**：显示数量、写入体积、粗估耗时；无冲突时为"开始恢复 / 取消"，有冲突时提供三选：
   - **恢复安全项**：只恢复未变化的资源；
   - **强制全部恢复**：连同已变化项一并用备份覆盖（会丢弃这些改动）；
   - **取消**。
3. **异步执行**：分片复制备份（含 `.meta`）覆盖原文件、带进度、可中断；**末尾一次性重导入**（这一步受 Unity 限制会短暂占用主线程）。
4. **状态更新**：整任务全部恢复 → 任务标记为 `RolledBack`；部分恢复 → 仅把实际恢复的资源标记为"已回滚"，任务保留原状态以便后续再处理。

> 资源表里也可对**单个资源**点 **恢复**：直接用该任务备份覆盖当前文件与 `.meta`（单张、瞬时，同样有确认框）。

## 显存监控

- **测试连接** / **刷新显存** 会读取 ComfyUI `/system_stats` 的显存信息。
- 执行期间每 2 秒轮询一次，实时显示**实测占用峰值**与可用显存。
- 触发告警的情况（仅提示，不强制阻止）：
  - 预计输出图集单边 > Unity 纹理上限 **16384**（必然失败，需降低最大边长）。
  - 运行中可用显存逼近上限（可能 OOM，建议降低最大像素/边长后从历史任务继续）。

## 常见问题

**Q：提示"图集页 0 输出为 AxB，预期约 CxD (Nx)"？**
输出实际倍率与「预期放大倍率」不一致导致尺寸校验失败。多数是把预期倍率填错了（比如工作流实际是 1.44x，却填了 4x）。把「预期放大倍率」改成工作流真实的输出倍率即可。

**Q：显存 OOM / ComfyUI 崩溃？**
降低「最大像素数」或「最大边长」以缩小单页。执行区会实时显示占用峰值与可用显存；若逼近上限，可中断后调小参数，再从「历史记录」继续。

**Q：处理很慢 / 超时？**
适当调大「单页超时」；单页越大、倍率越高越慢。也可减小图集尺寸以降低单页耗时。

**Q：中断后能继续吗？**
能。见[安全中断与续跑](#安全中断与续跑)。

## 已知限制

- 仅处理 `.png` / `.jpg` / `.jpeg`。
- 图集构建、拆分、提交覆盖运行在主线程，处理超大图集时编辑器会短暂卡顿；ComfyUI 网络等待、扫描、恢复复制阶段是异步的。
- 恢复/提交的**结尾资源导入**（`AssetDatabase.Refresh`）受 Unity 限制在主线程执行，量大时会短暂占用主线程。
- 图片解码 / `GetPixels32` / Importer / Sprite 元数据受 Unity API 限制只能在主线程执行。
- 输出图集单边受 Unity 纹理上限 16384 约束。
- 暂存文件与备份使用 GUID 短名（`staged/{guid}`、`backup/{guid}`）以规避 Windows 260 字符路径上限。
